FHIR R4 资源互联引擎 接口帮助

HL7 FHIR R4（4.0.1）标准互操作接口：本系统既可作为 Client 出向上报，也可作为 Server 入向开放资源调阅。
1. 介绍与作用 2. 出向 / 入向 3. 参数配置 4. 鉴权 5. 接口清单 6. 测试方法 7. 错误码

1. 介绍与作用

FHIR（Fast Healthcare Interoperability Resources）是 HL7 组织发布的医疗数据交换标准。本模块让门诊系统与区域平台、上级医院、第三方应用以标准资源（Patient / Encounter / Condition / Observation / MedicationRequest / ImagingStudy）交换数据，是系统对外互联的核心通道。

2. 出向 / 入向

方向说明
出向（Outbound）本系统作为 Client，把挂号、诊断、医嘱等组装为 FHIR Bundle 异步 POST 到目标 FHIR Server。
入向（Inbound）本系统作为 Server，对外暴露 /api/fhir/r4/*，供外部按标准读取资源。

3. 参数配置

入向开放

  • 启用入向开放：总开关。开启后受保护资源端点才可访问（/metadata 与 /oauth/token 免认证）。
  • 长期静态 Token / API Key 列表（可选）：离线联调用。每行 5 段 名称,Token,过期时间,启用,Scope，后 3 段可省略。点「追加 Token」自动生成一行。
  • OAuth2 客户端列表（可选）：标准 client_credentials 客户端。每行 client_id,client_secret,Scope（Scope 省略默认 system/*.read）。点「追加客户端」自动生成一行。
  • 令牌签名密钥（可选）：服务端签发自包含令牌的 HMAC-SHA256 密钥。可点「生成密钥」手工生成，留空则首次颁发令牌时自动生成并保存。
  • IP 白名单（可选）：留空不限来源；配置后仅白名单（支持单 IP 与 CIDR）可访问受保护端点。
入向至少配置一种凭证（静态 Token 或 OAuth2 客户端），否则入向数据端点将全部拒绝访问。

4. 鉴权（SMART-on-FHIR / OAuth2）

受保护端点在请求头携带凭证，两种方式任选：

Authorization: Bearer <access_token>
X-API-Key: <token>

方式一：OAuth2 取令牌（推荐，令牌有效期 7200 秒）

curl -X POST http://127.0.0.1:8000/api/fhir/oauth/token \
  -d "grant_type=client_credentials" \
  -d "client_id=pacs" \
  -d "client_secret=PacsSecret123" \
  -d "scope=system/ImagingStudy.read system/Patient.read"

返回：

{ "access_token": "...", "token_type": "Bearer", "expires_in": 7200, "scope": "..." }

方式二：静态 Token：直接把「长期静态 Token 列表」中的 Token 原文作为 X-API-Key 或 Bearer 值。

只填 Token 原文即可，不要带 Bearer 前缀或 X-API-Key: 头名，系统会自动识别。

Scope 规则

  • 读取某资源需 system/<资源名>.read，如 system/Patient.read。
  • system/*.read 放行全部资源读取；* 放行一切。
  • Scope 不足返回 403 forbidden。

5. 接口清单（入向）

方法路径说明
GET/api/fhir/r4/metadataCapabilityStatement（免认证）
POST/api/fhir/oauth/tokenOAuth2 令牌（免认证）
GET/api/fhir/r4/Organization机构（医院名称，name）
GET/api/fhir/r4/Patient/{id}患者资源（id = patient-{门诊号}）
GET/api/fhir/r4/Encounter?patient={门诊号}就诊检索，支持 _include=Encounter:patient
GET/api/fhir/r4/Condition?patient=诊断（ICD-10）
GET/api/fhir/r4/Observation?patient=检验结果 / 生命体征（category=laboratory|vital-signs）
GET/api/fhir/r4/MedicationRequest?patient=处方医嘱
GET/api/fhir/r4/ImagingStudy?patient=影像检查（支持 DICOM UID / modality / started）
GET/api/fhir/r4/DiagnosticReport?imagingStudy=|patient=影像报告（conclusion 检查诊断、performer 报告医生；检查所见/临床诊断/开单信息见 extension）

通用检索参数：_count（默认 20，上限 200）、_page/_offset、_sort、_include；未识别参数静默忽略。返回 Bundle(searchset)，含 total 与 link[self|next]。

资源划分与标识约定：检验结果仅以 Observation 暴露，影像检查仅以 ImagingStudy 暴露（互不混淆）。ImagingStudy.identifier：urn:dicom:uid=StudyInstanceUID、ACSN=检查号（申请单号 JC…）、VN=门诊号（就诊流水号）；报告号以独立 system urn:clinic:identifier:report 提供（非检查号）。Patient.identifier：MR=患者号（patient_no）、NI=身份证号。Observation 不带 category 时返回检验+体征全部。

6. 测试方法

① 免认证元数据：

curl http://127.0.0.1:8000/api/fhir/r4/metadata

② 静态 Token 检索：

curl -H "X-API-Key: <你的Token>" \
  "http://127.0.0.1:8000/api/fhir/r4/Patient?_count=5"

③ OAuth2 令牌 + 带 _include 检索：

TOKEN=$(curl -s -X POST http://127.0.0.1:8000/api/fhir/oauth/token \
  -d "grant_type=client_credentials&client_id=pacs&client_secret=PacsSecret123" \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8000/api/fhir/r4/ImagingStudy?patient=FHD0001&_include=ImagingStudy:patient"

也可在「状态总览 → 连通性测试」中按当前表单值一键探测入向本地端点。

7. 错误码与排查

状态含义处理
401Token 缺失/无效/过期检查凭证是否正确、是否过期；响应头 WWW-Authenticate 会提示
403未启用 / IP 不在白名单 / Scope 不足 / 凭证禁用核对开关、白名单与 Scope
404资源不存在或不支持的资源类型核对资源名与 id
400参数非法核对必填参数
500服务器内部错误查看接口管理 → HIS/同步监控的入向审计日志
所有错误均返回标准 OperationOutcome 资源，issue[].code 为 security/forbidden/not-found/invalid 等标准值。
