HL7 v2.x 消息通信 接口帮助

HL7 v2.x 消息通道：出向发送 ADT/ORM 并校验 ACK；入向通过 MLLP 守护进程或 HTTP 代理接收 ORU^R01 结果并自动回填。
1. 介绍 2. 出向 3. 入向 4. ORU 报文与危急值 5. 测试

1. 介绍

HL7 v2 是检验/检查设备与 HIS/LIS 之间最常用的消息标准。本系统入向解析后自动把结果写入检验报告，并对危急值触发闭环。

消息方向用途
ADT^A04 / A08出向患者建档 / 信息更新
ORM^O01出向处方 / 检查 / 检验开单
ORU^R01入向观察结果回传（检验报告）
ACK入向应答MSA|AA 成功 / AE 应用错误 / AR 拒绝（附 ERR）

2. 出向配置

  • 传输通道：MLLP over TCP（默认，双闭环 ACK）或 HTTP(S) POST。
  • 远端主机 / 端口 / 超时：目标 HL7 服务地址。
  • MSH-3 ~ MSH-6：发送应用/机构、接收应用/机构。

3. 入向配置

  • MLLP 本地监听端口：守护进程 tools/cli/hl7_mllp_server.php 监听端口（默认 2575）。启动：php tools/cli/hl7_mllp_server.php。
  • HTTP 代理鉴权 Token（可选）：HTTP 代理端点 POST /api/external/hl7/receiver 的 Token；留空则仅校验 IP 白名单。Token 原文作为 X-HL7-Token 或 Bearer。
  • IP 白名单：MLLP 与 HTTP 代理共用。

4. ORU^R01 报文与危急值闭环

报文段：MSH、PID、PV1、OBR（申请单）、OBX（结果项）。系统按 OBR-2 申请单号回填结果；当 OBX-8 异常标志为 HH/LL/CRIT/PANIC 或数值越过项目危急值上下限时，自动写入危急值流水并通知接诊医生。

5. 测试方法

MLLP（nc / netcat）：（帧以 0x0B 起、0x1C 0x0D 止）

{
  printf '\x0B'
  printf 'MSH|^~\\&|LIS|LAB|CLINIC|HOSP|20261001150000||ORU^R01|MSG00042|P|2.4\r'
  printf 'PID|1||FHD0002||李娜||19860322|F\r'
  printf 'OBR|1|JY2026100114224692|9001|肝功能^肝功能\r'
  printf 'OBX|1|NM|ALT^谷丙转氨酶(ALT)||500|U/L|7-40|HH|||F\r'
  printf '\x1C\x0D'
} | nc 127.0.0.1 2575

预期 ACK：MSA|AA|MSG00042|已回填 1 项检验结果；已触发 1 条危急值流转

HTTP 代理：

curl -X POST http://127.0.0.1:8000/api/external/hl7/receiver \
  -H "X-HL7-Token: <Token>" -H "Content-Type: text/plain" \
  --data-binary $'MSH|^~\\&|LIS|LAB|CLINIC|HOSP|20261001150000||ORU^R01|M1|P|2.4\rPID|1||FHD0002\rOBR|1|JY...\rOBX|1|NM|ALT^谷丙转氨酶(ALT)||500|U/L|7-40|HH|||F'
失败时返回 MSA|AE|...（应用错误）或 MSA|AR|...（缺 MSH 等拒绝），并附 ERR 段说明原因。
